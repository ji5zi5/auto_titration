# Development Timeline and Troubleshooting

# 개발 흐름과 장애 지도
정확한 모든 커밋 날짜를 복구한 연대기가 아니라 대화·현재 문서로 확인한 단계별 흐름이다.

## 1. 펌프 없는 데이터 수집에서 연속 주입 연동으로
수동 적정에서 프레임별 실제 부피를 모르면 이론부피 라벨과 시점을 연결하기 어렵다는 논의가 있었다. 중간에 멈춘 수동 기록을 단순 선형 보간해 일정유량 실험처럼 만들지 않기로 했다. 이후 완성 펌프 시작/정지 명령과 녹화를 연결했다.

## 2. 웹 화면과 센서
카메라 권한 허용만으로 Mini2 raw 스트림이 열리는 것은 아니다. Windows 수집기 포트가 안 열리면 웹 proxy10061/스트림 대기가 나타날 수 있다. Arduino 미연결 문제와 카메라 수집기 중단을 분리한다.
서버 시작 후 Arduino 연결 시 포트 재탐색이 필요하다. IDE/시리얼 모니터가 포트를 점유할 수 있다. 관련 프로그램 강제 종료는 당연한 자동 조치로 간주하지 않는다.

## 3. ROI 시행착오
네모 이동/물체검출 bbox/픽셀 마스크는 다르다. 투명 비커·반사·손·얼굴이 자동 마스크에 섞였다. YOLO, RGB/HSV 기반 클릭, 올가미 보정 등을 시험했지만 사용자는 사각형 수동 ROI 복원을 요구했다.
일반영상과 열화상은 해상도·시야각·위치가 다르므로 같은 픽셀 좌표를 단순 복제하면 안 된다. 실제 자료는 각각 고정한 ROI다. 자동후보는 준비단계 보조이지 항상 정확한 용액 경계 증거가 아니다.
404 ROI polygon API 오류는 UI와 collector 배포 불일치 가능성을 보여준다. 동일 폴더의 frontend/backend를 확인해야 한다.

## 4. 표시 지연과 저장 누락
표시25fps와 센서-to-screen 지연은 다르다. YOLO 또는 RGB 분석·렌더링이 큐를 밀 수 있다. JPEG35 설정은 영상 압축품질이지 FPS나 온도정확도가 아니며 사용자가 낮은 화질을 지적했다.
FIFO를 전체에 무조건 쓰면 화면이 늦어지고 최신-only를 기록에 쓰면 실험 데이터가 손실된다. 그래서 화면과 기록을 나눴다. 종료 직후 파일을 확정하지 말고 잔여 기록을 처리한다.

## 5. 모델·보고서 정정
과거 낮은 MAPE가 진짜 검증인지, 정답을 읽었는지, 진행률이 들어갔는지 반복 확인했다. 최종 후보 모델의 feature 누수 제외와 대규모 사후 선택 편향은 별개 문제다. 보고서에서 함께 공개한다.
지시약 및 표준 농도는 원 CSV와 사후 진술이 다를 수 있다. 원본을 조용히 덮어쓰지 말고 정정 기록을 별도로 둔다.

## 6. 자동정지 및 저속단계
초기 no-auto-stop 요구는 이후 선택형 기능 추가 요청으로 변경됐다. 기존12회는 여전히 수동 종료다. 최근 slow-stage 옵션은 V/RATE capability 필요, 빠름→느림→펄스 단계의 명목 유량을 분할 누적하며 대기 중 부피를 더하지 않는다.
0.5초 고정대기는 안정화 관측을 통해 충분함을 증명한 값이 아니다.
