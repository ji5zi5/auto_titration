# Windows 종말점 근처 미세 주입 및 선택형 자동 정지 검증

## 근거 유형과 현재 상태

이 문서에서는 다음 세 유형을 섞어 쓰지 않는다.

| 근거 유형 | 확인한 내용 | 현재 상태 | 허용되는 표현 |
|---|---|---|---|
| **측정값** | 실제 펌프가 토출한 물의 질량·부피, 실제 5스텝 방울 크기, 위치별 정밀도, 정지 후 추가 토출량 | **새 펄스 제어와 주사기 위치별 보정에 대한 측정값 없음** | 물 보정 전에는 수치·정밀도·개선 효과를 제시하지 않음 |
| **소프트웨어 검증** | 상태 전환, `STEP 5` 명령·응답, 안전 정지, CSV 기록, 펌웨어 스텝 상한 | 하드웨어 없는 단위·통합시험 통과 | **소프트웨어 구현 및 건식 시험 완료** |
| **명목·모의 계산** | 설정 유량 0.99 mL/s와 명목 100 step/s를 적용한 스텝-부피 환산 | 계산식 확인 | **5 step = 명목 0.0495 mL** |

따라서 0.0495 mL를 실측값, 실제 한 방울 부피, 토출 정확도 또는 정밀도로 인용하지 않는다.

## 구현 목적

4차 서면컨설팅에서 지적한 연속 주입의 과주입 위험을 줄이기 위해, Windows 수집기에 **연속 주입 → 접근 감지 → 미세 펄스 주입 → 혼합 대기 → 재판정** 흐름을 추가하였다. 이 기능은 사용자가 웹 화면에서 자동 정지를 선택했을 때만 작동한다.

## 동작 순서

1. 녹화를 시작하되 펌프는 정지 상태로 유지하고, 초기 1초 이상 일반 카메라 ROI의 기준색을 보정한다. 이 구간의 명령 기반 주입량은 0 mL로 기록한다.
2. 기준색과 실시간 모델 입력이 모두 유효할 때만 펌웨어 안전 제한 `G <ms>`를 먼저 설정하고 `b` 명령으로 연속 주입한다. 기준색 확보가 3초 안에 끝나지 않거나 모델 입력이 누락되면 펌프를 시작하지 않는다.
3. 실시간 모델 점수가 0.20 이상이면 접근 구간으로 판단하고 `c` 명령으로 연속 주입을 멈춘다.
4. 연속 주입으로 들어간 적정액이 섞이도록 0.50초 동안 기다린 뒤 센서값을 다시 판단한다.
5. 종말점 확인 조건이 충족되지 않으면 Arduino에 `STEP 5`를 보내 5스텝만 움직인다. 원래 동작 기준으로 주입 명령은 `b`, 되감기는 `a`이며 펌웨어의 펄스 방향도 `b`로 고정한다. Windows는 연속 주입 방향과 설정된 펌웨어 펄스 방향이 다르면 자동 펄스를 시작하지 않는다.
6. Windows 시리얼 경로가 `STEP ACCEPTED 5`와 `PUMP STOPPED PULSE_COMPLETE`를 모두 확인한 뒤 다시 0.50초 동안 혼합과 센서 안정화를 기다린다. 완료 응답이 없으면 같은 `STEP`을 재전송하지 않고 `c`를 보낸 뒤 오류로 정지한다.
7. 종말점이 확인되지 않으면 5~6단계를 반복한다.
8. 모델 점수가 0.30 이상일 때 시작된 색 변화가 0.4초 이상 지속되면 `c`를 보내고 기록을 종료한다. 후보가 시작된 뒤에는 순간적인 모델 점수 하락보다 실제 색 변화의 지속 여부를 확인한다.

이론 당량점 부피, 최종 진행률과 정답까지의 거리는 정지 조건으로 사용하지 않는다. 수동 밀기·되감기와 자동정지를 끈 일반 녹화는 `c` 정지 명령 전까지 계속 동작한다. 자동정지를 켠 경우에만 보수적 최대 유량, 비상 주입 상한과 `G <ms>` 펌웨어 제한을 적용한다. 자동 경로의 비상 주입 상한은 100 mL, 펌웨어 제한은 최대 120초이며 측정 결과가 아니다.

## 명목상 미세 주입량

펌웨어의 한 스텝 주기는 HIGH 5000 마이크로초와 LOW 5000 마이크로초를 합한 0.01초이므로 명목상 초당 100스텝이다. 설정 유량을 0.99 mL/s로 둘 때 소프트웨어가 환산하는 값은 다음과 같다.

```text
명목 부피/스텝 = 0.99 mL/s ÷ 100 step/s = 0.0099 mL/step
5스텝 펄스 명목 부피 = 0.0099 × 5 = 0.0495 mL
5스텝 안전 상한 부피 = 0.0105 × 5 = 0.0525 mL
```

CSV의 계산 주입량에는 명목값 0.0495 mL를 더하고, 최대 주입량을 넘지 않는지 판단하는 보수적 누적량에는 0.0525 mL를 더한다. 두 값 모두 설정 유량과 모터 명령으로 계산한 값이며, 실제 한 방울 또는 실측 토출량을 뜻하지 않는다. 실제 펄스 부피는 주사기 마찰, 잔량, 호스 압력, 노즐, 점도와 표면장력의 영향을 받으므로 별도의 물 또는 질량 측정이 필요하다.

## 주사기 위치별 물 보정 절차 — 후속 측정용

> 이 절차와 아래 빈 표는 **검증 계획 및 기록 양식**이다. 작성 시점에 측정을 수행하거나 결과값을 채우지 않았으므로 완료된 실험 근거로 인용하지 않는다.

### 위치 정의

주사기를 최대 충전한 피스톤 위치를 이동률 0%, 배출 예정 종점을 100%로 두고 다음 세 위치를 사용한다. 각 반복에서 실제 주사기 눈금과 피스톤 시작·종료 위치도 함께 기록한다.

| 위치 | 기준 피스톤 이동률 | 의미 |
|---|---:|---|
| 초기 | 10% 부근 | 잔량이 많은 구간 |
| 중간 | 50% 부근 | 잔량이 절반인 구간 |
| 말기 | 90% 부근 | 잔량이 적은 구간 |

### 측정 순서

1. 실제 적정과 같은 주사기, 호스, 노즐, 모터 설정을 사용하고 증류수로 라인을 채운 뒤 기포를 제거한다.
2. 장치를 같은 높이와 자세로 고정한다. 물 온도, 저울 분해능, 주사기 눈금, 호스·노즐 식별 정보를 기록한다.
3. 초기·중간·말기 위치마다 `STEP 5`, `STEP 10`, `STEP 20`, `STEP 50`을 각각 **최소 10회** 반복한다. 순서 효과를 줄이도록 명령 크기의 실행 순서를 섞고, 각 반복의 시작 위치를 해당 위치 범위로 다시 맞춘다.
4. 각 명령 전후 수집 용기의 질량 차이 `Δm`을 측정한다. 물 밀도 `ρ(T)`의 출처와 값을 함께 기록하고 `V = Δm / ρ(T)`로 부피를 환산한다. 온도별 밀도를 적용하지 않으면 부피 대신 질량 결과만 보고한다.
5. 각 펄스 뒤에는 실제 제어와 같은 0.50초 대기와 사전에 정한 방울 안정화 시간을 적용한다. 저울 분해능이 개별 5스텝 펄스를 구분하지 못하면 여러 펄스를 한 블록으로 측정한 뒤 펄스 수로 나누되, 이 결과를 **개별 펄스 정밀도**로 해석하지 않는다.
6. 각 위치·명령 크기에서 평균, 표본 표준편차, CV를 계산한다. 명령 스텝 수와 평균 실측 부피의 선형 회귀에서 기울기, 절편, 결정계수 `R²`, 최대 절대 잔차를 기록한다.
7. 정지 지연은 정지 명령 `c` 뒤 별도 용기에 추가로 나온 물을 사전에 정한 동일 시간 동안 받아 **정지 후 추가 토출량**으로 측정한다. 목표 부피가 독립적으로 정해진 시험에서는 `최종 실측 부피 - 목표 부피`를 부호 오차로 기록하고, 양의 값만 `overshoot = max(0, 최종 실측 부피 - 목표 부피)`로 요약한다.
8. 위치별 결과를 비교해 피스톤 위치에 따른 평균 토출량, CV, 선형성, overshoot 차이를 확인한다. 합격 기준은 결과를 보기 전에 정하며, 기준을 정하지 않은 경우 기술 통계만 보고한다.

제공 CSV 양식은 각 위치와 각 명령 조합마다 100회 펄스를 묶은 독립 측정행을 기본 10개씩 만든다(총 3 위치 × 4 명령 × 10회 = 120행). `pulse_steps`가 개별 명령 크기이고, `pulse_count`는 한 측정행에 묶은 펄스 수이며, `commanded_steps = pulse_steps × pulse_count`이다. 분석 JSON의 `position_command_group_counts`와 `insufficient_position_command_groups`에는 위치·명령별 관측 수, 요구 수, 부족 수가 기록된다. 한 조합이라도 10회 미만이면 CLI도 경고하므로 해당 결과를 완전한 위치별 보정 근거로 해석하지 않는다.

### 계산 정의

```text
평균 = sum(V_i) / n
표본 표준편차 = sqrt(sum((V_i - 평균)^2) / (n - 1))
CV(%) = 100 × 표본 표준편차 / 평균
5스텝 편향(mL) = 5스텝 평균 실측 부피 - 0.0495
부호 오차(mL) = 최종 실측 부피 - 독립적으로 정한 목표 부피
overshoot(mL) = max(0, 부호 오차)
```

`0.0495 mL`는 5스텝 편향 계산의 **명목 기준**일 뿐 실측 참값이 아니다. 선형성은 `R²`만으로 판단하지 않고 기울기, 절편과 잔차를 함께 확인한다.

## 구현 범위

- Arduino 펌웨어는 기존 `a`, `b`, `c` 명령을 유지하면서 `STEP 1~200`을 추가하였다.
- `STEP` 방향은 원래 주입 방향 `b`로 고정되어 있고, 호스트의 연속 주입 방향과 다르면 자동 펄스를 거부한다.
- 펌웨어는 요청된 스텝만 수행한 뒤 드라이버를 자동 비활성화한다.
- Windows 시리얼 브리지는 `STEP ACCEPTED n` 응답을 확인하고 실패 시 안전 정지를 수행한다.
- Windows 시리얼 브리지는 이어지는 `PUMP STOPPED PULSE_COMPLETE`까지 확인하며, 응답이 불확실한 `STEP`은 자동 재시도하지 않는다.
- 연속 `a`·`b`와 정지 `c`도 펌웨어 확인 응답을 요구한다.
- 연속 주입은 `GUARD ARMED <ms>`와 `PUMP RUNNING <방향> <ms>`의 방향·시간 한도가 모두 정확히 일치할 때만 시작된 것으로 인정한다. 펌웨어가 더 긴 한도로 시작했거나 응답이 다르면 즉시 `c`를 보낸다.
- 이미 주입 중일 때 들어온 중복 시작은 Windows에서 거부하고, 펌웨어에서도 같은 방향 명령은 기존 제한시간을 갱신하지 않는 확인 응답만 보낸다. 반대 방향은 명시적으로 정지한 뒤에만 다시 시작할 수 있다.
- `STEP` 완료 응답 대기와 별도의 비상정지 쓰기 경로를 두어, 응답 대기가 막혀도 `c`가 먼저 전달될 수 있게 하였다. 이 경우 펄스 완료 여부는 불확실로 기록하고 같은 `STEP`을 재전송하지 않는다.
- 연속 주입 시작에서는 펌웨어 가드 확인 뒤의 최종 취소 검사와 `a`·`b` 바이트 쓰기를 비상정지와 같은 직렬화 잠금으로 중재한다. 따라서 정지가 먼저 취소 세대를 게시했다면 방향 바이트를 쓰지 않고, 방향 바이트가 이미 승인되었다면 반드시 그 뒤에 `c`가 기록되어 `c` 뒤에 늦은 `a`·`b`가 전송되는 순서 역전을 막는다. 방향 응답을 기다리는 동안에는 쓰기 잠금을 놓으므로 비상 `c`는 계속 선점할 수 있다.
- 펌웨어는 `G -1`, `G  -1`, `STEP -1`처럼 부호·공백·탭이 섞인 값을 숫자로 변환하기 전에 거부하고, 비어 있지 않은 ASCII 숫자열만 허용한다.
- CSV는 연속 구동 시간과 펄스 횟수·총 스텝 수·명목상 펄스 부피를 구분해 기록한다.
- 대기 시간에는 주입량이 증가하지 않도록 명령 기반 펌프 시간축을 사용한다.
- 한 녹화 세션 안에서 정지 후 다시 시작해도 이미 계산된 연속·펄스 주입량을 회당 최대부피에서 차감하므로, 재시작으로 부피 한도를 초기화할 수 없다.
- CSV 종료 처리가 진행 중인 `finalizing` 상태에서는 주입과 후퇴 시작을 모두 거부하여, 아직 닫히지 않은 세션의 부피 한도와 기록 경계를 우회할 수 없게 하였다.
- CSV 시작·종료 잠금을 센서 큐가 비워지는 동안에도 유지하고, 그 전환과 동시에 들어온 주입·후퇴 요청은 대기 후 실행하지 않고 즉시 거부한다.
- 녹화 종료 요청은 CSV 잠금을 기다리기 전에 비상 `c`와 안전가드 취소를 시작한다. 따라서 펌프 시작 응답이 지연 중이어도 종료 요청이 먼저 세대를 무효화하고, 아직 방향 명령을 보내지 않은 시작은 실제 구동으로 진행하지 않는다.
- 자동 판정 콜백과 사용자의 녹화 종료·펌프 후퇴가 동시에 실행될 때는 물리 정지를 먼저 요청하고 자동정지 판정을 해제한 뒤 CSV 전환 잠금을 획득한다. 각 정지 경로에는 별도 소유 토큰을 부여하고, 지연된 센서 큐 정리를 위한 정지 래치는 해당 CSV 세션 번호가 일치할 때만 해제한다. 따라서 자동 경로가 먼저 끝나도 수동 경로가 남아 있으면 정지 의도가 유지되고, 이전 세션의 늦은 콜백이 새 세션의 종료 래치를 지울 수 없다. 자동 콜백이 판정 잠금을 보유한 채 CSV 전환을 기다리는 상황과 한 경로가 먼저 CSV를 닫는 상황을 의도적으로 만든 회귀시험에서도 교착·중간 재시작 없이 종료됨을 확인하였다.
- 자동정지 하드웨어 경로는 정답·이론 당량점·진행률·미지 시료 농도 입력이 포함된 모델을 거부하고, 선택한 적정 종류에 해당하는 모델과 유효한 센서 특징이 모두 있어야 동작한다. 표준용액 농도와 현재 명령 주입량은 실험 중 알 수 있는 값이므로 허용한다.
- 자동 펌프 시작 뒤 필수 센서·색상·모델 계산이 실패하면 최대 부피까지 계속 돌지 않고 즉시 정지 요청과 기록 종료를 수행한다. 최신 프레임만 남기는 분석 대기열에서도 한 번 발생한 필수 입력 오류는 정상 후속 프레임이 덮어쓸 수 없도록 세션별 실패 상태로 고정한다.
- 연속 구간과 펄스 구간 모두 명목 유량과 별도의 최대 유량 상한으로 계산한 보수적 누적 부피를 사용한다. 최대 유량 상한이나 펄스당 부피 상한이 없으면 자동 펌프를 시작하지 않는다.

## 검증 범위와 한계

펌웨어 계약, 펄스 상태 전환, 시리얼 명령 확인, 주입량 기록과 자동 정지 연동은 하드웨어 없는 단위·통합시험으로 확인하였다. 기존 12회 습식 적정은 사람이 정지한 자료이므로 새 미세 주입 기능의 정밀도 근거가 아니다.

2026-08-06에 펌웨어를 Arduino UNO 대상으로 실제 컴파일하고, 핵심 정지·펌웨어·Windows 서버 회귀시험 210개와 펄스 제어·실시간 모델·웹 UI를 포함한 관련 회귀시험 245개를 다시 실행하였다. 캐시 파일을 제외한 깨끗한 환경에서 전체 저장소 회귀시험 1,185개도 통과하였다. 최신 펌웨어의 Arduino Uno 컴파일 결과는 프로그램 저장공간 4,174 byte, 전역 변수 443 byte였으며 오류가 없었다.

```bash
arduino-cli compile --fqbn arduino:avr:uno auto_titrator/arduino_stepper --warnings all
.venv/bin/python -m unittest -v tests.test_auto_stop tests.test_pulse_control tests.test_typewise_live_model tests.test_windows_live_collect tests.test_website_assets tests.test_arduino_firmware
```

기존 12개 CSV에는 새 펄스 제어가 적용되지 않았으므로 `tools/pulse_replay_analysis.py`로 반사실적 재생만 별도 수행하였다. 12회 모두 불러왔고 endpoint 양성 행이 있던 10회 중 0.4초 연속 양성 조건과 가상 `STEP 5` 정책으로 정지할 수 있었던 자료는 1회뿐이었다. 이 결과는 현재 라벨의 지속성이 제한적임을 보여 줄 뿐 실제 자동정지 성능이나 펄스 제어의 개선 효과를 증명하지 않는다. 재현 가능한 전체 결과는 `data/analysis/report_evidence_no_new_wet/pulse_replay_simulation.json`에 저장하였다.

후속 물 보정은 다음 양식과 명령으로 기록할 수 있다.

```text
docs/report_evidence_no_new_wet/pump_position_calibration_template.csv
.venv/bin/python tools/pump_calibration.py --write-position-template docs/report_evidence_no_new_wet/pump_position_calibration_template.csv
.venv/bin/python tools/pump_calibration.py --input-csv <측정완료CSV> --nominal-ml-per-step 0.0099 --output data/raw/pump-position-analysis.csv --summary-output data/raw/pump-position-analysis.summary.json
```

양식 생성 기본값과 허용 최솟값은 위치·명령 조합당 10회이다. 더 많이 반복하려면 `--template-repeats <10 이상>`을 지정한다.

따라서 보고서에서는 이 기능을 **소프트웨어 구현 및 건식 시험 완료**로만 표현한다. 실제 장치에서 5스텝이 0.0495 mL를 토출하는지, 한 방울에 해당하는지, 정지 지연과 과주입량이 얼마나 줄었는지는 습식 반복시험 전에는 주장하지 않는다.
